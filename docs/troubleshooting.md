# 오류 처리와 데이터 확인

[처음으로](../README.md) · [제공 범위](coverage.md)

## 자주 만나는 응답

| 상태·코드 | 확인할 내용 |
| --- | --- |
| 401 | DATA 키를 넣었는지, 앞뒤 공백이 없는지, 키가 폐기되지 않았는지 확인하세요. 포털 비밀번호는 API 키가 아닙니다. |
| `BUILDER_SCOPE_DENIED` | 행사 범위 밖입니다. 경로·시장·생성 옵션을 확인하세요. 반복 재시도하지 마세요. |
| `MARKET_NOT_ENTITLED` | 해당 키에 허용되지 않은 시장입니다. `/key`에서 시장을 확인하세요. |
| `BUILDER_SINGLE_QUERY` | `POST /query`의 `queries` 배열에는 한 항목만 넣으세요. |
| `BUILDER_STORED_ANALYSIS_ONLY` | `include_summary=true` 대신 `/disclosures/{id}/analysis`를 사용하세요. |
| 400 | 필수 파라미터·종목·기간·지원 시장이 맞는지 확인하세요. `/disclosures`에는 한국 `symbol`이 필요합니다. |
| `404 ANALYSIS_NOT_AVAILABLE` | 해당 공시에 공개된 저장 분석이 없습니다. 빈 상태를 표시하고 새 분석 생성을 시도하지 마세요. |
| 다른 404·빈 목록 | 해당 종목·기간에 데이터가 없을 수 있습니다. 0으로 바꾸거나 수치를 추정하지 마세요. |
| `410 ENDPOINT_RETIRED` | 제공이 종료된 API입니다. 글로벌 임상시험 등 종료 경로를 제거하고 재시도하지 마세요. Builder에서는 먼저 범위 밖으로 거절될 수 있습니다. |
| `BUILDER_ENDED` | 행사 이용이 종료되었습니다. 코드 재시도가 아닌 이용 조건 확인이 필요합니다. |
| `BUILDER_QUOTA_EXCEEDED` | 현재 단계의 총량이 소진되었습니다. 짧은 간격으로 재시도해도 복구되지 않습니다. |
| 429 | 팀 전체 요청을 줄이고 `Retry-After` 이후에 다시 시도하세요. 최대 2개 동시 요청을 지키세요. |
| 503·네트워크 오류 | 잠시 후 제한된 횟수만 재시도하세요. 간격을 늘리고, 계속 실패하면 요청 ID와 함께 문의하세요. |
| 쿼리 결과 `NOT_READY` | 데이터가 아직 준비되지 않았습니다. 빈 상태를 표시하고 잠시 후 제한된 횟수만 다시 조회하세요. HTTP 200이어도 성공 데이터가 아닙니다. |

예제 CLI는 요청을 자동으로 반복하지 않습니다. 네트워크 타임아웃은 20초이고, 오류에는 HTTP 상태·오류 코드·요청 ID·`Retry-After`만 표시합니다. 키나 원본 오류 응답 전체는 출력하지 않습니다. 성공 응답을 파일로 저장했다면 공개 저장소에 올리지 마세요.

직접 구현할 때는 429의 `Retry-After`를 먼저 따르고, 503에는 예를 들어 2초·4초·8초처럼 최대 3회만 재시도하세요. 모든 요청을 여러 워커가 동시에 재시도하지 않도록 팀 서버에서 조절하세요. 400·401·403·404와 단계 총량 소진·종료는 자동 재시도하지 마세요.

## 응답과 페이지네이션

- 일반 조회는 `data`와 `meta`를 읽습니다. 목록은 `next_cursor`·`has_more`가 있으면 같은 필터에 `cursor`만 추가해 다음 페이지를 요청하세요.
- 예제는 첫 페이지만 요청합니다. 큰 목록을 시작부터 끝까지 자동 수집하지 마세요.
- `POST /query`는 HTTP 상태와 함께 각 `results` 항목의 `ok`, `error`, `status`도 확인하세요. HTTP 200만으로 성공으로 처리하면 안 됩니다.
- MCP는 JSON-RPC `error` 및 도구 결과의 `isError`를 확인하세요.
- `meta.as_of`, 단위·통화·기준 기간·출처를 화면에 보존하세요. 분기 단독값과 누적값, 연결·별도 재무제표를 섞지 마세요.
- 캘린더의 날짜·시간대와 공시 접수 시각은 다릅니다. 예정 일정은 변경될 수 있습니다.

## 자주 묻는 질문

**인증번호 입력 화면을 닫았어요.**

같은 브라우저에서는 신청 페이지의 **인증 이어하기**, 다른 기기에서는 새 인증 이메일의 **인증 계속하기**를 누르세요. 번호가 만료되거나 잠기면 복귀한 화면에서 다시 받을 수 있습니다. 인증번호뿐 아니라 복귀 링크도 공유하지 마세요. 예전 이메일에 링크가 없다면 신청 페이지에서 다시 신청할 수 있으며, 기존 비밀번호·권한·사용량을 초기화하지 않습니다.

**분석을 요청하면 새 AI 결과가 생성되나요?**

아니요. Builder는 이미 검토·공개된 분석을 조회합니다. 없는 분석은 404이며, 새 생성·번역·기사 작성은 제공하지 않습니다.

**미국 시세가 안 되는데 스크리너 안의 가격은 써도 되나요?**

스크리너·섹터 결과에 포함된 가격·시가총액·밸류에이션은 사용할 수 있습니다. 미국 현재가·가격 이력·스트리밍 API를 직접 조회하는 것은 제외됩니다.

**한국 실적 캘린더를 `/earnings?market=KR`로 호출하면 되나요?**

`/earnings`는 미국 실적 일정입니다. 한국 IR 일정은 `/ir-calendar`를 사용하세요. 두 일정의 의미는 동일하지 않습니다.

**화면에서 API를 직접 불러도 되나요?**

키가 브라우저 번들에 들어가지 않도록 본인 프로젝트의 서버에서 호출하세요. `NEXT_PUBLIC_`·`VITE_` 등 공개 환경변수에 키를 넣지 마세요.

**Python 인증서 오류가 나요.**

OS/Python의 신뢰 인증서 설치를 확인하세요. macOS의 python.org 배포판은 함께 설치된 `Install Certificates.command`가 필요할 수 있습니다. TLS 검증을 끄지 마세요.

**문의할 때 무엇을 보내나요?**

팀명(공개 가능 범위), 시각·시간대, 메서드·경로(비밀값 제외), HTTP 상태, 오류 코드, 요청 ID, 기대한 동작을 보내 주세요. 계정 문제는 [비공개 문의](https://openapi.chickstockfi.com/request)를 사용하세요. 키·비밀번호·세션·전체 응답 덤프는 보내지 마세요.
